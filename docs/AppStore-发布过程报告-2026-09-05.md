## 二、后台资源创建（developer.apple.com，经 Chrome 浏览器自动化完成）

本阶段全部通过本机 Chrome（专用 profile + CDP 远程调试端口）自动化操作，
用户只需在弹出窗口中完成 Apple ID 登录与双重认证。

### 步骤 1：注册 App ID

- **网站**：developer.apple.com → Account → Certificates, Identifiers & Profiles → Identifiers
- **填写材料**：

| 字段 | 填写值 |
| --- | --- |
| Platform | 全平台（iOS, iPadOS, macOS, tvOS, watchOS, visionOS——新版后台默认，无需选择） |
| Description | `FrameScoop` |
| Bundle ID | Explicit（显式）→ `com.framescoop.app`（与工程 `PRODUCT_BUNDLE_IDENTIFIER` 完全一致） |
| Capabilities | 无需勾选（新版后台 macOS 沙盒自动处理，没有 App Sandbox 勾选项） |

- **意义**：App ID 是应用在整个 Apple 生态里的唯一身份证。描述文件、证书、App Store
  应用记录全都以它为中心；bundle id 一旦用于发布不可更换（更换会使本机沙盒容器、
  文件夹书签、照片库授权全部脱钩）。

### 步骤 2：创建「Mac App Distribution」证书（应用签名）

- **本地准备**：`openssl` 生成 **RSA-2048** 密钥对 + CSR
  （首次用了 EC 曲线被门户拒绝：「CSR algorithm/size incorrect. Expected: RSA(2048)」）
- **网站**：developer.apple.com → Certificates → 创建 → 类型选「Mac App Distribution」
- **填写材料**：上传 CSR 文件；下载 `.cer`；私钥 + `.cer` 导入本机登录钥匙串并配对
- **钥匙串身份**：`3rd Party Mac Developer Installer` 之外的
  `3rd Party Mac Developer Application: Alpha Liu (VZ272K534R)`
- **意义**：app 可执行内容的签名身份。描述文件必须包含它；App Store 审核通过
  这个签名链验证「这个包确实来自账号持有人」。

### 步骤 3：创建「Mac Installer Distribution」证书（安装包签名）

- **网站**：同上（同一 CSR/密钥复用）
- **钥匙串身份**：`3rd Party Mac Developer Installer: Alpha Liu (VZ272K534R)`
- **意义**：Mac 特有的第二层签名——macOS 上架包是 `.pkg` 安装包，
  app 内容签一次、安装包外壳再签一次，两道签名缺一不可。

### 步骤 4：创建 Mac App Store 描述文件（Provisioning Profile）

- **网站**：developer.apple.com → Profiles → 创建
- **填写材料**：

| 字段 | 填写值 |
| --- | --- |
| 类型 | Mac App Store Connect |
| Profile Type | Mac |
| App ID | `FrameScoop`（VZ272K534R.com.framescoop.app） |
| 证书 | 1 张（Mac App Distribution 证书） |
| 名称 | `FrameScoop Mac App Store` |

- **安装**：下载 `.mobileprovision`，以 UUID 命名放入
  `~/Library/MobileDevice/Provisioning Profiles/`
- **意义**：把「App ID + 签名证书 + 分发方式」绑定成一份 Apple 签发的授权文件。
  构建时被嵌入 app，App Store 用它判断「这个 bundle id 的 app 是否被允许以该证书分发」。

## 三、出包（本机命令行）

### 步骤 5：Archive（xcodebuild）

- **命令**：`xcodebuild archive -configuration Release`，带
  `DEVELOPMENT_TEAM=VZ272K534R`、手动签名指定证书哈希 + profile UUID
- **结果**：`build/FrameScoop.xcarchive`，app 已由
  `3rd Party Mac Developer Application` 签名、嵌入「FrameScoop Mac App Store」描述文件
- **意义**：编译 Release 产物 + 完成嵌入签名，是打包的原料。

### 步骤 6：打包 .pkg

- **第一次尝试**：`xcodebuild -exportArchive`（Xcode 官方导出）——**失败**
  - 错误 1：团队 ID 默认值写成了个人团队 2L5K72XW64，与 profile 团队不匹配（已修正为 VZ272K534R）
  - 错误 2：Xcode 开发者账号会话过期（"Your session has expired"），导出时身份选择错乱，
    把 Installer 证书拿去与描述文件校验，报「Provisioning profile doesn't include
    signing certificate '3rd Party Mac Developer Installer'」
- **最终方案**：改用传统 Mac App Store 打包链路
  `productbuild --component <归档里的已签名 .app> /Applications --sign <Installer 证书哈希> FrameScoop.pkg`
  ——不依赖 Xcode 账号会话，直接包装已签名的 app
- **结果**：`build/appstore/FrameScoop.pkg`（2.7MB），
  `pkgutil --check-signature` 验证签名链 =
  `3rd Party Mac Developer Installer: Alpha Liu (VZ272K534R)` ✅
- **意义**：得到可直接上传 App Store Connect 的分发包。

## 四、过程中踩的坑（备忘）

1. **账号下有两个团队**：个人团队（2L5K72XW64）与组织团队（VZ272K534R）。
   发布资源全部建在 VZ272K534R 下；个人团队是 Apple ID 自带属性，**无法删除**，也不应删
   （本机 Apple Development 调试证书挂在它下面）。
2. **CSR 必须 RSA-2048**：EC 曲线 CSR 会被门户拒绝。
3. **新版门户 App ID 默认支持全平台**，且没有 App Sandbox 能力勾选项（沙盒由
   entitlements + 描述文件链路自动生效）。
4. **API Key 权限**：Developer 角色的 API Key 对 bundleIds/certificates 等端点
   只读（写操作 403），创建资源走了浏览器自动化；若以后想全 API 自动化，需 Admin 角色 Key。
5. **exportArchive 依赖 Xcode 账号会话**：会话过期会导致签名身份选择错乱。
   用 productbuild + productsign 替代即可稳定出包。
6. **浏览器自动化经验**：Apple 门户是重 JS 应用，表单填充需用原生 value setter +
   input/change 事件；下载 .cer/.mobileprovision 用页面内 fetch（带会话凭据）比
   依赖 Chrome 下载管理器更可靠。

## 五、遗留待办（用户侧，无法代做）

1. **App Store Connect 协议/税务/银行**：同意付费 App 协议、填税务表（W-8BEN 类）、
   收款银行信息——免费应用也必须完成，否则无法提审。
2. **上传包**：App Store 下载「Transporter」→ 拖入 `build/appstore/FrameScoop.pkg`。
3. **创建应用记录**：App Store Connect → 我的 App → 新建（bundle id 选 `com.framescoop.app`，
   SKU 随意，如 `framescoop-001`）。
4. **填元数据**：描述、关键词、分类（摄影/图形与设计）、支持 URL、隐私政策 URL、
   截图（≥1280×800）、1024×1024 图标、内容分级问卷、App 隐私问卷（本应用无网络无跟踪，如实填）。
5. **选构建 → 提交审核**（审核一般 1-3 天）。
